📋  Campaigns

What is a campaign?

A fundraising run — like Spring Uganda Run 2026. Each campaign gets its own page on the site (/spring-uganda-run), its own donation goal, and its own Zeffy link. Think of it as a dedicated fundraiser with a start and end date.

What is the slug?

The URL identifier. Whatever you put in Slug becomes the page address. Example: slug spring-uganda-2026 → visitors go to yoursite.com/spring-uganda-2026. Use lowercase letters and dashes only — no spaces.

How do I update how much money has been raised?

Click Edit on the campaign → change Raised so far ($) → Save. The progress bar on the campaign page updates automatically. Do this after each Zeffy payout or whenever you check your total.

What does "Active" mean?

The active campaign is the featured one shown on the home page campaign card. Only one campaign should be active at a time. When a run ends, uncheck Active on the old one and check it on the new one.

What is the Zeffy URL?

The donation form link from zeffy.com for that specific campaign. Log into Zeffy → open the fundraiser → copy the URL from your browser. Paste it here. Every "Give" button on that campaign page will point to it.

How do I start a new campaign?

1. Create the Zeffy fundraiser first and copy its URL.
2. Click New campaign here → fill in name, slug, story, goal, and Zeffy URL.
3. Check Mark as active when you're ready to feature it.
4. The campaign page goes live at /[your-slug] immediately.

📝  Blog & Updates

What are posts for?

Field updates, testimonies, prayer requests, stories from the run. They appear in the Updates section on campaign pages. Use them to keep donors informed and excited — even a short "we arrived safely in Uganda" post goes a long way.

What's the difference between Draft and Published?

Draft — saved but invisible on the site. Good for writing ahead of time.
Published — live on the site immediately. Check the Publish immediately box when you're ready. You can unpublish any time by editing and unchecking it.

Can I write posts from the field on a phone?

Yes — the admin works on mobile. Go to yoursite.com/admin in your phone browser. The sidebar collapses on small screens; tap Blog & Updates to get to posts. Keep the body short for slow connections.

🖼  Photos

How do I add a photo?

Photos are added by URL — not file upload. Upload your photo to Google Drive, Dropbox, or any image host, get a direct link, paste it here. Google Drive tip: share the file publicly → right-click → Copy link.

Which category should I use?

Field — general: anything from the field that doesn't fit below.
Field — distribution: photos of Bibles being handed out.
Field — prayer: prayer circles, worship moments.
VillageServer kit: the solar case, Raspberry Pi, router setup.
Team: runners, staff, group shots.
Other: events, churches, donors.

⚙️  General

How fast do changes appear on the site?

Instantly. The site fetches live from Supabase on every page load — there's no cache to clear, no deploy to trigger. Save here, open the site in a new tab, it's there.

What if I make a mistake?

Just edit the item and save again. Nothing is permanent until you click Delete — and even then there's a confirmation popup. If you accidentally delete something important, it can be restored directly in the Supabase table editor at supabase.com.

Someone else needs access — can I share the password?

Yes, but everyone shares the same password (ADMIN_PASSWORD in Vercel). There's no per-user login. To change the password, update the env var in Vercel and redeploy. Let anyone who had the old password know.

How do I get to this page without knowing the URL?

Scroll to the very bottom of the main site → find Built by ArkiTech Solutions in the footer → click it 3 times quickly. That's the hidden shortcut. Don't share it publicly.

Prerequisites
0What you need before starting›
  • Raspberry Pi 3, 4, or 5 (any model with ethernet port)
  • MicroSD card — 16 GB or larger (32 GB recommended)
  • SD card reader for your laptop
  • Raspberry Pi Imager — free download from raspberrypi.com
  • Ethernet cable to plug Pi into your router during setup
  • Router that lets you reserve a static IP and open a UDP port
  • A public IP address (or DDNS hostname) for your internet connection — you'll forward port 51820
ℹ️  No monitor needed. Everything after the first boot is done over SSH from your laptop.
Part 1 — Boot the Pi
1Flash Raspberry Pi OS Lite (64-bit)›

Open Raspberry Pi Imager → choose OS → Raspberry Pi OS (other) → Raspberry Pi OS Lite (64-bit). Before writing, click the gear ⚙️ and set:

  • Hostname: villageserver
  • Enable SSH → Use password authentication
  • Username: pi   Password: something strong (write it down)
  • Locale / timezone: yours

Write to the SD card, insert into the Pi, plug in ethernet, power on.

✅  Lite = no desktop GUI. Smaller, faster, less battery drain on solar.
2SSH in & set a static LAN IP›

Find the Pi's IP in your router's client list (hostname villageserver), then SSH in:

ssh pi@<PI_CURRENT_IP>

Update the system:

sudo apt update && sudo apt upgrade -y

Reserve a static IP in your router's DHCP settings using the Pi's MAC address — e.g. 192.168.1.100.

⚠️  Also forward UDP port 51820 on your router to this LAN IP.
Part 2 — WireGuard Server
3Install WireGuard› 
sudo apt install wireguard -y
4Generate server keys› 
wg genkey | sudo tee /etc/wireguard/server_private.key | wg pubkey | sudo tee /etc/wireguard/server_public.key
sudo chmod 600 /etc/wireguard/server_private.key

Print and save both keys:

sudo cat /etc/wireguard/server_private.key
sudo cat /etc/wireguard/server_public.key
⚠️  Never share the private key. The public key goes on clients.
5Create server config — /etc/wireguard/wg0.conf› 
sudo nano /etc/wireguard/wg0.conf

Paste this (replace private key with yours from Step 4):

# WireGuard server — VillageServer Pi

[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = <SERVER_PRIVATE_KEY>
SaveConfig = false

# Route: forward traffic + NAT through ethernet
PostUp   = iptables -A FORWARD -i %i -j ACCEPT; iptables -A FORWARD -o %i -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -D FORWARD -o %i -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

# ── Clients (one [Peer] block per device) ──

[Peer]
# Phone — Person 1
PublicKey = <CLIENT_1_PUBLIC_KEY>
AllowedIPs = 10.8.0.2/32

Save: Ctrl+O then Ctrl+X. Lock it down:

sudo chmod 600 /etc/wireguard/wg0.conf
6Enable IP forwarding & start WireGuard› 
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
sudo systemctl enable wg-quick@wg0
sudo systemctl start wg-quick@wg0
sudo systemctl status wg-quick@wg0

Status should say active (running). Verify the interface:

sudo wg show
Part 3 — Client Setup (per device)
7Generate a key pair for each client›

Run on the Pi — one pair per phone/laptop:

# Replace "person1-phone" with a label for the device
wg genkey | tee /tmp/person1-phone_private.key | wg pubkey > /tmp/person1-phone_public.key
cat /tmp/person1-phone_private.key
cat /tmp/person1-phone_public.key

Copy the public key and add it as a new [Peer] block in wg0.conf on the server (Step 5 template). Then restart:

sudo systemctl restart wg-quick@wg0
8Client config file (paste into WireGuard app)› 
[Interface]
PrivateKey = <CLIENT_PRIVATE_KEY>
Address = 10.8.0.2/24
DNS = 8.8.8.8

[Peer]
PublicKey = <SERVER_PUBLIC_KEY>
# Your router's public IP (or a DDNS hostname)
Endpoint = <YOUR_PUBLIC_IP>:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
ℹ️  Each client gets its own IP: 10.8.0.2, 10.8.0.3 … and its own private key. AllowedIPs = 0.0.0.0/0 routes all traffic through the Pi. For LAN-only access use 10.8.0.0/24.
9Generate a QR code for the phone› 
sudo apt install qrencode -y
# Save the client config to a file first, then:
qrencode -t ansiutf8 < /tmp/person1-phone.conf

Open WireGuard app on the phone → tap + → Scan QR code. Point camera at the terminal. Done — no typing needed.

Part 4 — Wi-Fi Hotspot (optional, for offline village use)
10Turn the Pi into a Wi-Fi access point›
ℹ️  Only needed if people connect to the Pi over Wi-Fi directly (offline content library). Skip if everyone tunnels in over WireGuard remotely.
sudo apt install hostapd dnsmasq -y
sudo systemctl stop hostapd dnsmasq

Static IP on wlan0 — add to /etc/dhcpcd.conf:

interface wlan0
    static ip_address=192.168.4.1/24
    nohook wpa_supplicant

Create /etc/hostapd/hostapd.conf:

interface=wlan0
driver=nl80211
ssid=VillageServer
hw_mode=g
channel=7
wmm_enabled=0
macaddr_acl=0
auth_algs=1
ignore_broadcast_ssid=0
wpa=2
wpa_passphrase=ChangeMeNow
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP

In /etc/default/hostapd set:

DAEMON_CONF="/etc/hostapd/hostapd.conf"

Replace /etc/dnsmasq.conf:

interface=wlan0
dhcp-range=192.168.4.2,192.168.4.20,255.255.255.0,24h
sudo systemctl unmask hostapd
sudo systemctl enable hostapd dnsmasq
sudo systemctl start hostapd dnsmasq

Reboot — Pi broadcasts VillageServer Wi-Fi. Change password in hostapd.conf from ChangeMeNow.

Part 5 — Content Library
11Serve local content over the tunnel› 
sudo apt install nginx -y

Copy files (PDFs, audio, HTML) to the webroot:

# From your laptop to the Pi:
scp mybible.pdf pi@192.168.1.100:/var/www/html/

Connected clients open http://10.8.0.1 in their phone browser — content loads offline, no internet required.

✅  nginx and wg-quick auto-start on boot (from Steps 6 + enable above). Pi recovers fully after power loss.
Troubleshooting

WireGuard starts but client can't connect

Check: (1) UDP port 51820 forwarded on router to Pi's LAN IP. (2) Endpoint in client config is your current public IP — run curl ifconfig.me on Pi. (3) Run sudo ufw allow 51820/udp if ufw is enabled. (4) sudo wg show — the peer appears once a handshake succeeds.

Handshake says "latest: never"

Client public key in wg0.conf doesn't match the actual client private key. Regenerate the client key pair (Step 7), update the [Peer] block with the new public key, restart wg-quick@wg0, regenerate the client config, rescan QR.

Client connects but can't reach the internet

IP forwarding is off. Run cat /proc/sys/net/ipv4/ip_forward — should be 1. If it's 0, re-run Step 6. Also check: sudo iptables -t nat -L POSTROUTING should show a MASQUERADE rule for eth0.

How do I add a new device later?

SSH to Pi → generate new key pair (Step 7) → add new [Peer] block to wg0.conf with next IP (10.8.0.3, 10.8.0.4…) → restart wg-quick@wg0 → build client config (Step 8) → QR code (Step 9). Takes about 3 minutes.

How do I see who's currently connected?

Run sudo wg show. Each peer shows its last handshake and transfer stats. If latest handshake was within the last 3 minutes, the peer is actively connected (PersistentKeepalive = 25 s keeps it alive).
